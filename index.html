Network interface card simulator

C++ · OOP · Make · Introduction to Software Systems

Reads packets as text lines. A factory method builds the right L2, L3 or L4 object behind one abstract packet interface. Each layer checks its own checksum, MAC address or TTL, then hands the inner packet down. The IP mask decides whether a packet goes to the receive queue, the transmit queue or an open port’s memory. Outgoing packets get the card’s IP as their source, a lower TTL and a recomputed checksum.

Profile-guided binary optimizer

C++ · x86-64 · Intel Pin · team of two · Binary Translation & Optimization, 2026

The tool profiles a running program, then builds a second, optimized copy of its hot code and switches execution over to it. The course goal was to beat the native run, with no Pin attached, by more than 5% on at least one of five benchmarks.

  • Moved the optimized code onto huge pages, copied switch jump tables next to it, aligned hot loop heads and cut the cost of the profiling counters.
  • Added stack-slot load forwarding for unoptimized (-O0-style) code: reloads of locals from the stack are served from free registers instead of memory. It only turns on when a program looks like -O0 output, so optimized binaries are left alone.
  • Tracked down a crash in static glibc’s startup: the new code region collided with the heap’s randomized start address. Fixed by placing it 256 MB above the real program break.
  • Checked every benchmark output byte for byte against the native run, on each run.
bzip2: 15.1% faster than native, in 7 of 7 runs on the course VM

Branch profiler, and a crash that wasn’t in my code

C++ · Intel Pin · GDB · Computer Architecture

A probe-mode Pin tool that collects and ranks hot branches and loops in real ELF binaries. On one SPEC compiler binary it crashed with a SIGSEGV. Using GDB I traced it to the tool rewriting the first PLT stub, which the dynamic linker relies on for lazy symbol binding. Skipping the .plt routine fixed it.

Systolic-array convolution accelerator

VLSI project · team of two · Technion VLSI Lab · 2026/27, in progress

A configurable accelerator IP for neural-network convolution layers. Input pixels and weights move through a grid of multiply-accumulate units in a diagonal wave, so each value fetched from memory is used many times.

  • Split the core into units (caches, memory port, array, merge and quantize, pooling) and designed a state machine for each, plus the controller that runs loading and computing in parallel.
  • Wrote a cycle-by-cycle Python model of those state machines to measure array utilization before writing RTL, then used it to find and remove the stalls.
1×1 layer utilization: 40.7% → 95.8% after the fixes the model found
